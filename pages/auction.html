동시 입찰 환경의 최고가 갱신 처리

동시 요청에서 최고가가 잘못 갱신될 수 있는 문제를 Redis 구조와 갱신 방식 변경으로 해결했습니다.

JavaSpringRedisLua ScriptnGrinder

문제

초기에는 Redis ZSet에서 현재 최고가를 조회한 뒤 애플리케이션에서 입찰가를 비교하고 다시 저장했습니다. 조회와 저장 사이가 분리돼 있어 동시 요청이 들어오면 여러 요청이 같은 최고가를 기준으로 검증을 통과할 수 있었습니다.

기존

GET 최고가
↓
애플리케이션에서 비교
↓
저장

개선

현재 최고가 → String
+
입찰 이력 → ZSet
+
Lua Script

개선

현재 최고가와 입찰 이력을 목적에 맞게 분리했습니다. 최고가 조회·비교·저장을 하나의 Lua Script 안에서 처리해 동시 요청에서도 한 번의 원자적 연산으로 갱신되도록 변경했습니다.

검증

nGrinder를 이용해 기존 구조와 개선 구조를 비교했고, 응답시간과 TPS, 실패 요청 여부를 확인했습니다.
